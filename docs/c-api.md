# FlashRaw C and C++ API

`crates/flashraw-capi` exposes FlashRaw through a stable C ABI, with a header-only C++17
wrapper on top. Everything the Rust API offers for reading files is available: metadata,
embedded previews, decoding to raw or developed outputs, regions, threads, corruption policy,
calibration data and per-stage timings.

| file | what |
|---|---|
| `crates/flashraw-capi/include/flashraw.h` | C header (C99), generated by cbindgen and checked in |
| `crates/flashraw-capi/include/flashraw.hpp` | header-only C++17 RAII wrapper (`namespace flashraw`) |
| `libflashraw_capi.so` / `.dylib` / `flashraw_capi.dll` (+ `flashraw_capi.dll.lib`) | shared library |
| `libflashraw_capi.a` / `flashraw_capi.lib` | static library |
| `flashraw.pc`, `lib/cmake/flashraw/flashrawConfig.cmake` | installed by the CMake project |
| `examples/c/flashraw_info.c`, `examples/cpp/flashraw_decode.cpp` | examples (built in CI) |

## Building and linking

With cargo only:

```sh
cargo build --release -p flashraw-capi            # add --features gpu,jpegxl as needed
# -> target/release/libflashraw_capi.{so,dylib,a}  (Windows: flashraw_capi.dll, .dll.lib, .lib)
cc -I crates/flashraw-capi/include app.c -L target/release -lflashraw_capi -o app
```

Installing with CMake (cargo still does the compiling; CMake installs the libraries, both
headers, a pkg-config file and a CMake package):

```sh
cmake -S crates/flashraw-capi -B build/capi -DCMAKE_BUILD_TYPE=Release
cmake --build build/capi --config Release
cmake --install build/capi --prefix /usr/local
```

Options: `-DFLASHRAW_CARGO_FEATURES=gpu,jpegxl`, and `-DFLASHRAW_CARGO_TARGET_DIR=$PWD/target`
to reuse an existing cargo build directory.

Consuming the install:

```cmake
find_package(flashraw 0.1 REQUIRED)
target_link_libraries(app PRIVATE flashraw::flashraw)          # shared library
target_link_libraries(app PRIVATE flashraw::flashraw_static)   # static library
```

```sh
cc app.c $(pkg-config --cflags --libs flashraw)
```

Static linking needs the system libraries the Rust standard library uses. The CMake target
and the pkg-config file (`Libs.private`, use `pkg-config --static`) carry them; they are
reported by `rustc --print native-static-libs` (Linux: `-lgcc_s -lutil -lrt -lpthread -lm
-ldl -lc`; macOS: `-lSystem -lc -lm`; Windows: system libraries such as `kernel32`, `advapi32`,
`ntdll`, `userenv`, `ws2_32`). `examples/CMakeLists.txt` shows both link modes.

## Quick start (C)

```c
#include <flashraw.h>

flashraw_file *f = NULL;
if (flashraw_open_path("photo.NEF", NULL, &f) != FLASHRAW_OK) {
    fprintf(stderr, "%s: %s\n", flashraw_last_error_kind(), flashraw_last_error_message());
    return 1;
}
printf("%s %ux%u\n", flashraw_file_string(f, FLASHRAW_STRING_CAMERA),
       flashraw_file_raw_width(f), flashraw_file_raw_height(f));

flashraw_decode_options o;
flashraw_decode_options_init(&o);           /* always init before setting fields */
o.output = FLASHRAW_OUTPUT_RGBA8;
flashraw_frame *fr = NULL;
if (flashraw_decode(f, &o, &fr) == FLASHRAW_OK) {
    const uint8_t *rgba = flashraw_frame_data(fr);
    /* flashraw_frame_width(fr) x flashraw_frame_height(fr) x 4 bytes */
    flashraw_frame_free(fr);
}
flashraw_file_free(f);
```

## Quick start (C++)

```cpp
#include <flashraw.hpp>

flashraw::file raw = flashraw::file::open("photo.CR3");      // throws flashraw::error subclasses
flashraw::decode_options o;
o.output = flashraw::output_format::linear_rgb_f32;
o.threads = 4;
flashraw::frame img = raw.decode(o);
flashraw::span<const float> rgb = img.f32();                // C++17 span-like view, no copy
if (auto iso = raw.iso()) std::cout << "ISO " << *iso << "\n";
std::string all = raw.metadata_json();
```

Exceptions: `flashraw::error` (code, `kind()`, `detail_json()`) and one subclass per error kind
(`unsupported_format_error`, `corrupt_file_error`, `limit_exceeded_error`, `io_error`, ...).
`file` and `frame` are move-only; `get()` / `release()` give access to the C handles.

## API overview

All functions are prefixed `flashraw_`. Handles are opaque (`flashraw_file`, `flashraw_frame`).

**Library**: `version()`, `version_number()`, `abi_version()`, `supports(bytes, len)`,
`detect_format(bytes, len)`, `gpu_available()`, `stage_name()`, `output_format_name()`,
`output_format_parse()`, `error_kind_name()`, `string_free()`.

**Opening**: `open_path(utf8_path, opts, &file)` (memory-mapped), `open_memory(data, len, opts,
&file)` (zero-copy, caller keeps the bytes alive), `open_memory_copy(...)` (copies),
`open_options_init()` (safety limits: `max_dimension`, `max_samples`), `file_free()`.

**Metadata** (no pixel decoding):

| | |
|---|---|
| strings | `file_string(f, FLASHRAW_STRING_*)` (make, model, canonical make/model, camera, format, compression, software, firmware, serial, artist, copyright, capture time, lens make/model/serial, unique camera model); shortcuts `file_make/model/canonical_make/canonical_model/format_name` |
| geometry | `file_raw_width/height` (full buffer), `file_width/height` (default crop), `file_cpp`, `file_bits_per_sample`, `file_is_float`, `file_active_area`, `file_crop`, `file_masked_area_count/masked_area`, `file_orientation` (EXIF 1-8), `file_sensor_layout` |
| calibration | `file_cfa`, `file_black_level`, `file_white_level`, `file_white_level_max`, `file_white_balance` (as-shot), `file_white_balance_applied` (true when the camera already applied it to the samples: Sony lossless YCbCr M/S, Nikon sNEF; RGB outputs then develop with unit multipliers, and raw-output consumers must not apply it again), `file_color_matrix_count/color_matrix` (colour, forward, calibration), `file_color_source` |
| exposure | `file_iso`, `file_exposure_time`, `file_f_number`, `file_focal_length`, `file_focal_length_35mm`, `file_exposure_bias`, `file_lens_focal_range` (each returns `false` when not recorded) |
| previews | `file_preview_count`, `file_largest_preview`, `file_smallest_preview`, `file_preview_info`, `file_preview_bytes` (zero-copy) |
| tiles | `file_unit_count`, `file_unit` (rectangles to pass as decode regions) |
| everything else | `file_metadata_json()` — the escape hatch: all metadata (EXIF, GPS, DNG tags, orientation records, opcode lists, capabilities) as JSON, so new fields need no ABI change |

**Decoding**: `decode_options_init(&o)` then set `backend` (`FLASHRAW_BACKEND_*`), `output`
(`FLASHRAW_OUTPUT_RAW_U16`, `_RAW_F32`, `_NORMALIZED_F32`, `_LINEAR_RGB_F32`,
`_LINEAR_RGB_F16` (half floats), `_LINEAR_RGB16`, `_RGBA8`, `_RGB16` (16-bit display sRGB)),
`threads` (0 = all cores), `use_region` + `region`, `crop`, `demosaic` (`BILINEAR`,
`HALF_SIZE`), `apply_opcodes`, `corruption_policy` (`RECOVER` default, `STRICT`), limits,
for the RGB outputs `exposure` (EV), `black_point` and `white_point` (linear values mapped to 0
and 1; defaults 0, 0, 1), and `preview_fallback` (non-zero: RGB outputs of undecodable sensor
data, e.g. Nikon High Efficiency NEF, return the embedded full-size preview instead of
`FLASHRAW_ERROR_UNSUPPORTED_COMPRESSION`); `decode(file, &o, &frame)`. The display outputs
(`RGBA8`, `RGB16`) have the orientation applied; the linear ones keep the sensor orientation
(`frame_orientation`).

**Frames**: `frame_width/height/cpp`, `frame_sample_type` (`U8`/`U16`/`F16`/`F32`; `F16` =
IEEE half-float bit patterns in `uint16_t`, C++ `frame::f16_bits()`), `frame_data`,
`frame_data_len` (bytes), `frame_sample_count`, `frame_output_format`, `frame_active_area`,
`frame_crop`, `frame_origin`, `frame_cfa`, `frame_color_at`, `frame_black_level` (measured),
`frame_white_level`, `frame_white_balance`, `frame_white_balance_applied`, `frame_color_matrix*`, `frame_orientation`,
`frame_bits_per_sample`, `frame_is_incomplete`, `frame_warning_count/warning`, `frame_source`
(`FLASHRAW_SOURCE_SENSOR`, or `_PREVIEW` for a preview fallback),
`frame_samples_filled`, `frame_stats` (total and per-stage milliseconds, threads, sizes),
`frame_backend/postprocess_backend/simd`, `frame_json()`, `frame_free()`.

Sample data is row-major, `cpp` interleaved samples per pixel, no row padding, aligned for its
element type.

## Errors

Fallible functions return a `flashraw_status`: `FLASHRAW_OK` (0) or an error code. Codes 1-11
correspond one-to-one to the Rust library's error kinds (`UnsupportedFormat`,
`UnsupportedCompression`, `CorruptFile`, `InvalidMetadata`, `CameraUnsupported`,
`GpuUnavailable`, `OutOfMemory`, `LimitExceeded`, `NotAvailable`, `InvalidArgument`, `Io`);
`FLASHRAW_ERROR_INTERNAL` (12) reports a caught panic (a bug; the handle is still safe to free)
and `FLASHRAW_ERROR_OTHER` (13) a kind newer than the header.

Details of the last failure **on the calling thread**:

- `flashraw_last_error_message()` — human-readable message;
- `flashraw_last_error_kind()` — kind name, e.g. `"CorruptFile"`;
- `flashraw_last_error_detail_json()` — structured cause when known, e.g.
  `{"kind":"truncated","unit":"strip","index":3,"offset":...,"expected":...,"available":...,"file_len":...}`;
- `flashraw_last_error_code()`; `flashraw_clear_last_error()`.

The strings stay valid until the next failing call on the same thread. Successful calls do not
clear the last error. Getters that return a value (dimensions, pointers, counts) return 0 /
`false` / `NULL` on error and set the last error too. NULL pointers and out-of-range enum
values are reported as `FLASHRAW_ERROR_INVALID_ARGUMENT`; no input can cause undefined
behaviour except dangling pointers and buffers smaller than declared.

Under the default `FLASHRAW_CORRUPTION_RECOVER` policy, truncated or corrupt sensor data still
produces a frame: missing samples are zero-filled and `flashraw_frame_is_incomplete()` is true,
with one warning per damaged unit. `FLASHRAW_CORRUPTION_STRICT` turns that into
`FLASHRAW_ERROR_CORRUPT_FILE`.

## Memory ownership

| returned | owner | valid until |
|---|---|---|
| `flashraw_file *` | caller | `flashraw_file_free()` |
| `flashraw_frame *` | caller | `flashraw_frame_free()` (independent of the file: frames may outlive it) |
| `const char *` from `file_*` getters | the file | `flashraw_file_free()` |
| `const uint8_t *` from `file_preview_bytes` | the file (points into the input) | `flashraw_file_free()` |
| `const void *` from `frame_data`, `const char *` from `frame_*` | the frame | `flashraw_frame_free()` |
| `char *` from `*_json()` | caller | `flashraw_string_free()` |
| `const char *` from `version`, `detect_format`, `*_name` | library (static) | forever |
| last-error strings | thread-local | next failing call on that thread |

`flashraw_open_memory()` does not copy: the input must stay valid and unmodified until
`flashraw_file_free()` returns. `flashraw_open_memory_copy()` copies; `flashraw_open_path()`
maps the file read-only (do not truncate it while the handle is open).

## Threading

- A `flashraw_file` may be used from any number of threads at once: all functions taking
  `const flashraw_file *` are thread-safe, including concurrent `flashraw_decode()` calls on the
  same file (each produces its own frame).
- Frames are immutable and independent; read them from any thread.
- `flashraw_file_free()` / `flashraw_frame_free()` must not race with other uses of the same
  handle.
- Each decode uses a worker pool: `threads = 0` uses all cores, `threads = N` a pool of N
  workers (pools are cached per size). Concurrent decodes share the cores.
- The last error is per thread.

## ABI stability policy

FlashRaw follows semantic versioning; within a major version (and, while at 0.x, within a minor
version) the C ABI only grows:

1. **Functions** are never removed or changed in signature. New functions may be added.
   Deprecated functions keep working until the next major version.
2. **Enums** are passed as `int32_t`. Existing values never change meaning and are never
   reused; new values may be added. Code must handle unknown values (`*_UNKNOWN`,
   `FLASHRAW_ERROR_OTHER`).
3. **Opaque handles** hide all internal layout.
4. **Plain structs without a `size` field** (`flashraw_rect`, `flashraw_cfa`,
   `flashraw_black_level`, `flashraw_color_matrix`) are frozen.
5. **Versioned structs** (`flashraw_open_options`, `flashraw_decode_options`,
   `flashraw_preview_info`, `flashraw_decode_stats`) start with `uint32_t size`. New fields are
   only appended. The library reads/writes only the first `size` bytes: a caller built against
   an older header gets defaults for fields it does not know; a caller built against a newer
   header is accepted as long as the fields this library does not know are zero (otherwise
   `FLASHRAW_ERROR_INVALID_ARGUMENT`, so an unsupported option is never silently ignored). Their
   first published sizes are pinned by a test.
6. **JSON** documents only gain keys.
7. `FLASHRAW_ABI_VERSION` (header) / `flashraw_abi_version()` (library) change only for an
   incompatible change, which the rules above exclude within a major version. Check them at
   startup if you load the library dynamically.

`flashraw.h` is generated from the Rust sources by cbindgen
(`crates/flashraw-capi/cbindgen.toml`); CI regenerates it and fails if the checked-in copy
differs.

## Safety

The Rust side treats everything crossing the boundary as untrusted: every pointer is checked
for NULL, every enum value is validated, every body runs under `catch_unwind` (a panic is
returned as `FLASHRAW_ERROR_INTERNAL`, never unwound into C), and the decoders themselves have
FlashRaw's usual bounds checking and allocation limits. The `unsafe` code in the crate is
confined to dereferencing caller pointers, with a `SAFETY:` comment on each block.

## Tests

- `crates/flashraw-capi/tests/capi.rs` calls the exported functions from Rust: metadata, all
  outputs, regions, previews, versioned structs (older and newer layouts), NULL and invalid
  arguments, corruption policies with structured error details, concurrent decodes of one
  file, malformed inputs, and (with `FLASHRAW_CORPUS`) a corpus sample against the Rust API.
- `crates/flashraw-capi/tests/examples.rs` compiles the C example against the static library
  and the C++ example against the shared library (`-Wall -Wextra -Werror -pedantic`), runs
  them, and compiles both headers in strict C99/C11 and C++17/C++20 modes.
- CI (`c-api` job, Linux/macOS/Windows) builds and installs the library with CMake, builds the
  examples with `find_package(flashraw)`, runs them, and checks that the header is up to date.
